# Hallow Overlay

A see-through stats panel over your games - part of the Hallow family with [Hallow Hub](https://github.com/Dom428/hallow-hub), [Hallow Vault](https://github.com/Dom428/hallow-vault), [Hallow Mixer](https://github.com/Dom428/hallow-mixer) and [Hallow Toolkit](https://github.com/Dom428/hallow-toolkit).

- **MIC MUTED** warning and now playing (from Windows, or from Hallow Mixer when it runs - instant with Mixer 3.14+), FPS and 1% lows, CPU, GPU load and temperature, RAM, ping, session time, clock
- GPU core / memory clocks, power draw (W and % of the limit) and VRAM (NVIDIA), and a frame-time graph of the last 5 seconds with stutters in red
- Updates itself from GitHub releases (once a day, always asks first, checks the SHA-256)
- FPS comes from Windows' own frame events (ETW, the same ones PresentMon reads - DirectX, plus the graphics kernel's present events for Vulkan / OpenGL) - no admin prompt; Windows only allows it for admins and the Performance Log Users group, otherwise FPS stays hidden
- Shows only while a game runs (or always); one line or a column, three sizes; Ctrl+Shift+O to hide (all hotkeys can be changed)
- **Put it anywhere**: 9 spots (top / middle / bottom x left / centre / right), any screen (found by its monitor id, so re-ordering screens doesn't move it; the main screen while the saved one isn't connected) and an edge offset slider - or **Move it**: drag the panel or its "Drag me" card (settings, tray / Hallow menu, optional hotkey); it snaps to the spots and the screen's edges and centre lines (Shift / Alt: no snapping), arrow keys nudge 1 px (Shift 10 px), Enter / Esc / Done end it, and it's click-through again right after (also on focus loss or after 2 minutes idle). Saved as spot + offset as a share of the screen, so it survives resolution and DPI changes; a panel put somewhere free keeps the edges nearest the screen's edges, so it comes back to exactly the same place after a restart or in a game even when it's a different width (1.19). Every move is saved straight away (atomically) - drag, arrow keys, Done / Enter, or move mode ending by itself - and it says where: "Saved for <game>" or "Saved as your usual spot"; Reset position puts it back
- **Game server**: which server the game is talking to (from Windows' own Winsock events for the game's processes - same rules as FPS), its region from the host name (no online lookup), ping (or the nearest hop that answers, shown with ~), loss, "stalls" and the game's up / down traffic; the IP stays hidden by default
- **Benchmark** (Ctrl+Shift+F9 start / stop): average FPS, 1% and 0.1% lows, frame-time percentiles and a chart, saved as PNG + CSV in `Documents\Hallow Overlay\Benchmarks`; optional CSV log of every stat (`Documents\Hallow Overlay\Logs`)
- **Match summary**: when a game closes, a one-line summary on the panel; Match history (every session of 2 minutes or more: FPS, ping, loss, stalls, servers, temperatures, load) with a Servers view - kept in `%APPDATA%\HallowOverlay\matches.json`, the last 5 in status.json
- **Light and dark mode** (1.20) for the settings windows: they follow the family switch in Hallow Toolkit (`mode` in `%APPDATA%\Hallow\theme.json`: Light / Dark / Same as Windows, live), or your own choice in Settings > Look (Follow Hallow / Light / Dark). The in-game panel always stays dark and see-through
- **Light mode readability fixes** (1.21): accent-coloured buttons and selected options use the family light fill (the accent, or for accents like violet that no text colour reads on at 4.5:1, the accent darkened to 4.5:1 on white with white text); settings sliders use the darkened accent
- **Battery chips from Hallow Gear** (1.22): with [Hallow Gear](https://github.com/Dom428/hallow-gear) running, the panel shows a compact chip per device with a battery (mouse, headset) - **only when low** (the default: at or under Gear's low level, 20% unless changed there, and not charging), **always**, or **off** (Settings > Gear battery). While you play Gear doesn't pop up; its low-battery alert shows on the panel as one quiet line (`alert` in Gear's status.json) until the game ends. Read from `%APPDATA%\HallowGear\status.json` at most every 10 s - nothing is sent to Gear, and a missing, broken or stale file just means no chips. Since 1.23 earbuds and controllers (Bluetooth devices in Gear 1.1+) have their own icons
- **1.24 polish**: the frame-time graph has a dashed amber **1% low** line (the average of the slowest 1% of frames, the same rule as the FPS stat) and says it next to the median ("1% 65 fps"); Gear's chips sit together as small pills (amber / red tint when low, a bolt while charging, a plug on a cable, "~45%" when Gear estimated it, Gear 1.1+ `state` / `estimated` fields read too); now playing says **"Ad muted"** while [Hallow Mixer](https://github.com/Dom428/hallow-mixer) 3.27+ mutes a Spotify ad (`spotifyAdMuted` in its API / status.json) and "Advertisement" for an ad otherwise; **"Replay saved"** when Hallow Clips' status.json says so (optional `replaySaved` field - only if Clips didn't already flash it)
- Uses the Hallow accent colour picked in Hallow Toolkit (`%APPDATA%\Hallow\theme.json`, live); crash reports stay on this PC in `%APPDATA%\HallowOverlay\crashes` (newest 20, `lastCrash` in status) - nothing is sent anywhere
- **Layout editor**: order of the stats, your own labels, a colour per stat, text or text + a small graph of the last minute, text size
- **Your own hotkeys**: show / hide, benchmark, "only when something's wrong" and open settings - press-the-keys boxes in the settings, an Off per hotkey and Reset to defaults; a combo already used by another of its hotkeys or owned by another app is refused with a clear message and the old one keeps working
- Per game: its own spot (or "use my usual spot"), size and stats; "only when something's wrong" mode with your own limits; packet loss and jitter next to ping
- Its own click-through window - nothing is injected into games, so it's anti-cheat safe (borderless / windowed fullscreen needed; it tells you when a game is in exclusive fullscreen)
- Hallow family link: other Hallow apps can show / hide it and put short messages on it (named pipe `HallowFamily.Overlay.<user>` with `open` / `menu` / `invoke` / `quit` for Hallow Hub's one Hallow icon - `invoke move` starts / ends move mode, `move` does too for scripts but not over a game that has the focus unless `move force` -, `HallowOverlay.exe --cmd "ping"`, `%APPDATA%\HallowOverlay\status.json` with a `position` field (spot, offsets, edge offset, screen, the panel's rectangle, moving, click-through); while a game runs its `live` field has FPS, 1% low, ping and the server region - never the IP - for Hallow Remote's Live stats)

Built with the C# compiler that ships with Windows (.NET Framework 4.8): run `build.ps1`. No admin needed. `build.ps1 -Tests` also builds `tests\OverlayTests.exe` (1.24): stats formatting and warning colours, the frame-time graph and 1% low, position memory (spots, offsets, DPI, screens by monitor id, unplugging, the 1.19 anchor-width regression, atomic saves), Gear's status.json (old and new fields, "45%"), now playing with made-up Windows media sessions and Spotify ads, Mixer's "Ad muted", Clips' "Replay saved", Hub's notify lines (and a fake Hub pipe), the game hold, light / dark, the update text, settings migration from 1.0 / 1.14 / 1.23 files, and a test copy over the family pipe - nothing is shown on screen (`OverlayTests.exe unit` / `link`).
